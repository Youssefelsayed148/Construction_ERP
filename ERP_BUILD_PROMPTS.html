31 build prompts, one per phase

Each phase below is a self-contained prompt you hand to a coding agent (or read yourself) to execute that phase against the current repository — not a generic greenfield build. They follow ERP_EXPANSION_PLAN.html phase-for-phase and pull field lists, formulas, and workflow states from the construction_erp_agent_pack.

How to use this document

This is not one giant prompt. Run the phases in order — each one assumes the previous phases are already merged. Copy one prompt block at a time into your coding agent's session, let it finish, review the diff, and run the tests it wrote. Each prompt ends with its own commit step, so once the agent runs it you should see a new commit for that phase alone — verify it exists (git log -1) before copying the next block.

Ground rules for every prompt

These are not repeated in each block below — they are prepended automatically by convention. If you paste a prompt in isolation, paste this too.

Apply to phases 1–31 without exception

  1. Additive first. New tables/columns are nullable or defaulted; nothing existing is dropped until every caller has migrated and a parity test has passed. Where the plan says "remove," keep the old path as a compatibility shim (view, facade function, or fallback column) until callers are cut over.
  2. Transactional writes. Any operation touching multiple financial or stock records (GRN + stock movement, certificate + invoice, variation + budget) runs in one DB transaction. No partial writes.
  3. Soft-delete only. Controlled records get status = void/cancelled and a reason, never a hard DELETE, once they have participated in a workflow.
  4. Zero-broken-view policy. Every new page/endpoint must render/respond correctly with zero rows, one row, and a missing related record (no client, no consultant, no BOQ). No raw null, no unhandled 500, no blank page.
  5. Scope every new record. Carry company_id (or is globally implicit in this single-tenant deployment — confirm which), project_id where project-scoped, created_by_user_id, and location_id / work_package_id / cost_code_id where applicable.
  6. Route every write through the permission layer introduced in Phase 4, once it exists. Before Phase 4 lands, keep using the existing authorize() in backend/src/middleware/auth.js — do not invent a second, parallel check.
  7. Audit on write. Approvals, payments, contract/commercial changes, quantity certifications and agent actions write an immutable audit row (before/after) once Phase 4's audit_events exists; until then, keep writing to the existing activity_log.
  8. Inspect before you build. Before writing any migration or route change for a phase, grep/read the actual current file(s) named in that phase's prompt — table/column names may already differ slightly from what's written here since the codebase moves daily. docs/audit/ (produced by Phase 1, refreshed 2026-09-17) is the authoritative current-state reference — if it disagrees with a claim in one of these prompts, trust the audit and re-run Phase 1's steps yourself if enough time has passed since its date.
  9. Every module needs, before it counts as done: migration + validation, API, desktop UI, empty/loading/error state, permission checks, audit trail, search/filter/export, notifications hook, dashboard widget, and at least one automated test per new calculation or state transition.
  10. High-risk financial/contractual actions (issue PO, approve variation, send client invoice, record payment, approve certificate, delete a controlled document, close a project) are never executed autonomously by an agent without the human approval step the workflow defines — this applies from Phase 27 onward but design every write endpoint from Phase 6 on so it slots into that gate later.
  11. One commit per phase, no exceptions. Every prompt below ends with its own git add -A && git commit -m "Phase N: <title>" step. Do not let an agent carry uncommitted work from one phase into the next, and do not squash several phases into one commit — if phase 9's migration turns out to be wrong, you want to revert phase 9 alone, not phases 9–12 together.
