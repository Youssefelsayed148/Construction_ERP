The current system already contains a meaningful execution foundation including project setup,
phases, teams, milestones, BOQ, work orders, site reporting, QHSE, RFIs, submittals,
documents and property sales.

The target is to expand the existing system rather than create disconnected modules
around it.

112. TARGET TECHNOLOGY POSITION

The desired architecture should borrow the strongest concepts rather than copy one application:

     Procore-style: connected project objects, field execution, integrations and
         construction-specific APIs.

     Autodesk-style: configurable RFI/submittal workflows, linked issues/records and project
         collaboration.

     Oracle Aconex-style: rigorous documents, organizations, workflows and auditability.
     Primavera Unifier-style: enterprise cost/project controls.
     Modern MCP/API layer: first-class agent access rather than screen scraping. The

         current MCP specification is designed around stateless, routable servers with hardened
         authorization, and OpenAI currently supports custom MCP-powered apps and write
         actions in supported workspace configurations.

The result should therefore be:

        One construction company operating system. One source of truth. Every
        project has its own team, permissions, files, quantities, materials, contracts,
        invoices, workflows and dashboards. Every internal and external party
        receives only the interface and information relevant to them. Every major
        record is location-linked, auditable and actionable. The entire backend is
        API-first and MCP-ready so ChatGPT or another authorized agent can operate
        the ERP safely.
