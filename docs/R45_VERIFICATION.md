## Gaps, ordered by risk

1. **Unbounded and uncapped lists (4b, 4c).** `limit` is unvalidated on about 30 legacy endpoints (a large `limit` or a non-number reaches SQL), and 14 lists have no limit at all (`inventory/lots`, `approvals/pending`, variations, revisions). R4's "default 200, max 1,000, X-Total-Count everywhere" is not met, and the test that claims to guard it cannot see these routes.
2. **Load More returns duplicates (5h, 5g).** HR, payroll, maintenance and subcontractor endpoints ignore `offset`; the webhooks screen pages with a different scheme. Above one page of data, users see repeated or missing rows. Not covered by any page-level test.
3. **Admin labels missing in EN and AR (5b).** Nine dynamic keys render as missing-key text on variations, API-token, inventory-document and replenishment views. `i18n:check` cannot catch dynamic keys.
4. **No coverage of write paths on the admin screens (5f).** Update, deactivate, post/void, rotate-secret and sweep actions have no frontend test; only render, one denial, organization create and token display do.
5. **Service-account secrets stay on bcryptjs (3b)** and are never upgraded; unused `bcrypt` dependency remains.
6. **Sweep retention is not part of the two-process proof (3f)**; shutdown proof uses an IPC trigger, not an OS signal.
7. **No visual, RTL or browser validation ran (5c)**, and the admin table classes have no CSS.
8. **Stray untracked file `tatus --short`** in the repo root.
